FIELD NOTES · TOOLING · 31 AUG 2026 · 6 MIN READ

The graph was never counting the work

In August this studio pushed 156 commits. GitHub credited six of them to me. Nothing was broken, nothing failed, no error was raised — the other 150 commits were simply signed with an email address GitHub reads as somebody else. The interesting part isn't the vanity metric. It's that an identity mismatch is the quietest failure mode in any pipeline that attributes work.

A contribution graph is not a record of work. It is an index keyed on an email address, and I had been handing it the wrong key for a year. The reason it took a year to notice is that there is no failure state: the commit is written, the push succeeds, the diff lands, CI goes green. The commit is real and the work is real. It is just filed under a name that isn't yours, and nothing anywhere says so.

The rule, in full

GitHub counts a commit toward a profile only when all three of these hold:

  1. the commit's author email is a verified email on that account — not the pusher, not the repo owner, the author email baked into the commit object;
  2. the commit sits on the repository's default branch (or gh-pages);
  3. the repository is not a fork, and is yours or one you collaborate on.

Miss any of them and the commit is worth zero, silently. That third gate is the one everyone knows. The first is the one that quietly ate a year.

Three point eight percent. Every row is a different mechanism, and each one arrived from a different direction: a laptop configured during a degree, a cron job I wrote to be a good citizen and label its commits as a bot, a machine I set up in a hurry, a container I never configured because I never touched its shell.

The one that should worry you

The eight commits credited to the vendor are the ones worth staring at. Those came from cloud agent sessions — a container that ships with a git identity already set, because it has to have one. It is a sensible default and it is not mine, and no amount of configuring my machines reaches inside a container that gets built fresh for every session.

That generalises past attribution. A fleet of agents is a fleet of environments you did not personally set up, each carrying defaults from whoever built the image. Identity is the visible case because a graph renders it. The invisible cases — which credentials, which region, which model, which timezone a scheduled job thinks it's in — are the same class of bug with no picture attached.

Anything an agent produces on your behalf inherits an identity from somewhere. If you cannot name where, it isn't yours.

The fix is boring, which is the point

Three layers, in increasing order of how much they actually help:

  1. Set the global identity. Necessary, insufficient — it covers exactly the machines you remember to touch.
  2. Guard the commit, not the machine. A pre-commit hook in a global core.hooksPath that refuses any commit whose author email isn't on an allowlist. Now a wrong identity fails loudly at the moment it would have been written, instead of silently a year later.
  3. Pin it inside ephemeral environments. A session hook, committed to the repo, that sets the identity per checkout when a session starts. This is the only layer that reaches a container built after you stopped paying attention.

And then measure it, because a fix you can't see is a belief. The audit script now runs weekly and fails when under 90% of the week's commits are credited to me — the same shape as every other check in this studio: a cron, a threshold, a build that goes red.

What the graph is still not telling you

Fixing attribution recovered the history. It did not turn 156 commits into the number I'd have guessed, and that gap is worth being honest about: 156 commits over 30 days is about five a day landing on default branches. Work on an unmerged branch counts zero until it lands, and a squash merge collapses a forty-commit branch into a single counted commit. Commits in a local worktree count nothing at all until they are pushed.

Which is the real lesson, and it cuts against the fix: after all that work to make the graph accurate, the graph still measures how work is filed, not how much was done. Worth getting right, because being credited for your own work is not vanity. Worth not confusing for the work.
